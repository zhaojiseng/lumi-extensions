# 网关运行中保存全部配置：宿主联动方案

2026-10-11。用户已明确允许本方案与草稿模型查询的宿主联动范围。插件 0.1.0-dev.13 和本轮配套 Lumi 开发构建已实现供应商、模型、认证、Agent、整流、录制和双端口的运行中保存；实际检查见 GATEWAY_VALIDATION.md。

## 为什么需要主程序修改

供应商与认证保存走 GatewayLocalService 的私有事务；旧实现要求数据监听停止且没有进行中的请求，再关闭/重启核心。供应商、Agent 保存也受到 TLS 管理层限制。本轮同时修改受限宿主事务和插件提交入口，使真实保存生效。

## 具体修改范围

- main/electron/services/gateway-local.ts：先验证更新并准备受保护的凭据事务，按版本应用配置；运行中更新通过托管运行时应用，失败恢复既有配置和凭据。
- main/electron/services/gateway-runtime/management.mjs：序列化配置写入与监听状态变更；允许运行中保存供应商及 Agent，先验证配置、凭据和端口，再提交；目录查询沿用配置版本检查。
- main/electron/services/gateway-runtime/transport.mjs 与 types.d.mts：新请求采用新配置和认证快照；已接收请求继续使用原配置、模型、凭据和录制策略。改变数据端口时先绑定新端口，成功后停止旧端口接收新请求，并让原请求完成；端口占用时保留原监听。
- main/native/gateway-runtime/src/gateway.rs：协调原生配置与每个请求的准备快照，避免读请求体期间发生配置变更导致认证、模型和整流错配。更新持久化数据但不销毁进行中的请求及记录。
- main/electron/services/gateway-management.ts：保存后同步配对信息和管理连接；管理端口变化时由插件自动重连，撤回旧预览和会话结果。
- 独立插件：解除供应商/网关参数/Agent 保存限制，刷新保存版本和链路，并保留不相关编辑草稿。

保持现有插件 ID、公开 SDK 方法及权限。旧配置和旧插件兼容；新功能需要新的配套 Lumi 构建。独立插件仍单独安装。

## 验证与风险

使用隔离数据、假凭据和本机 TLS 上游验证：长 JSON/SSE 请求期间改变模型、认证、协议、整流及录制；新旧请求各自保持一致；供应商增删与 Agent 引用；数据/管理端口变更、占用、失败回滚；并发版本冲突；重连与退出生命周期。Windows 开发安装包与验证报告随本轮交付，macOS 构建未在本机执行。

持久化配置提交前先完成原生校验、数据/管理新端口绑定和加密配对文件准备。版本冲突、端口占用或提交失败保留原监听和凭据。已接收的 HTTP 请求固定使用接收时的配置、认证、模型、整流和录制策略；切换端口停止旧端口接收新请求，并保留已有 JSON/SSE 请求直到完成。
